    Explore scenarios

    Demo path: 4 scenes

    Present Discovery → Executable Memory → Phone Home → Reverse Shell. The controller triggers allowlisted actions in the management-cluster Kata VM. Argus observes from the HyperShift-hosted DPU cluster. Evidence-gated results show the matching native event and its actual severity; only alert scenarios require ALERT / HIGH.

    Discovery

    What it does. Execs bounded recon inside the Kata VM: uname -a, id, ps aux, then reads planted decoys at /decoys/credentials.txt and /decoys/runbook.txt. Named marker processes argus-gtc-discovery-* bookend the action. No network, no privilege escalation.

    On the Kata timeline. Filter jumps to Discovery. Look for INFO · EVENT process create/terminate on invisible-vm with names like argus-gtc-discovery-uname, -id, -ps, -decoys, plus file-descriptor opens on those decoy paths. Demo classification “Discovery (demo classification)” — not a native HIGH/ALERT.

    Executable Memory

    What it does. A Python process in invisible-vm writes inert bytes into an anonymous executable memory mapping and holds it for 45 seconds so Argus can sample it. It does not execute those bytes.

    Native evidence. Look for New Executable Anonymous Memory Mapped with message_type=EVENT and severity=WARNING, attributed to this Kata workload and run marker. The result says “Native evidence observed” only when a matching Argus record arrives; otherwise it says “No native event observed.”

    Phone Home

    What it does. Bash in invisible-vm opens a TCP connection to the in-namespace scenario-sink on port 4444, sends this run ID, and holds the connection for 20 seconds. Shell input and output stay off the socket. NetworkPolicy confines traffic to the demo namespace.

    Native evidence. Look for Network Connection Created with message_type=EVENT and severity=INFO, originating from this Kata workload and reaching the sink IP on port 4444. This is process-to-network visibility, not a reverse-shell alert. The result reports whether a matching native Argus event arrived.

    Compute Simulation

    What it does. A short CPU loop in the guest (5,000 integer squares to /dev/null). No network and no decoy writes. Marker processes argus-gtc-compute_simulation-start/end wrap it.

    On the Kata timeline. Sparse by design: process start/end for those markers on invisible-vm. That is the story — Argus still sees guest compute with no in-guest agent. Expect INFO · EVENT process lifecycle, not a native alert.

    Audit Evasion Attempt

    What it does. Starts bounded Bash (bash --noprofile --norc -i) on a real Kubernetes exec PTY in the Kata VM. It establishes a harmless history baseline, waits for an Argus scan, clears history while history is enabled, waits again, then disables history and remains alive for another scan. The unique disposable history file is removed when the session exits.

    Success requirement. After the bounded action completes, the server waits up to 45 seconds for raw Argus output containing message_type=ALERT, severity=HIGH, and exactly Shell History Disabled or Shell History Cleared. The full request can take about 80 seconds. If no match arrives, the result says “No native alert observed”; INFO/EVENT telemetry remains visible and is never promoted to an alert.

    Reverse Shell Simulation

    What it does. Opens interactive bash (bash -i) and redirects stdin/stdout over /dev/tcp to the in-namespace scenario-sink for about 20 seconds. NetworkPolicy keeps the traffic inside the demo namespace — no internet C2.

    On the Kata timeline. Filter includes both invisible-vm and scenario-sink. Look for process events (bash -i / argus-gtc-reverse_shell-*) and TCP connect events to the sink. Demo label is not a native alert. Argus 3.5 documents “Reverse Shell Detected” as HIGH — call that out only if the same event contains both message_type=ALERT and severity=HIGH.

    Shell History Tampering

    What it does. Pre-scripted history wipe in the Kata VM: set +o history, HISTFILE=/dev/null, history -c, then history -w. The session does not persist commands.

    On the Kata timeline. Process markers argus-gtc-shell_history-* on invisible-vm. You may also see file activity if Argus samples HISTFILE. Demo classification only unless a native HIGH/ALERT for history tampering shows up on the event.

    Decoy Modification

    What it does. Appends tampered-by-demo to the planted file /decoys/credentials.txt and cats it. Bounded write to a decoy, not a real secret.

    On the Kata timeline. File-descriptor open/write activity for /decoys/credentials.txt plus process markers argus-gtc-decoy_modify-* on invisible-vm. Typical signal is file events at INFO · EVENT. A content-change HIGH is optional, not assumed.

    Network Burst

    What it does. Sends 5 MiB of zeros (dd if=/dev/zero | nc) from the Kata VM to the in-namespace sink. Bounded; NetworkPolicy blocks anything outside the demo namespace.

    On the Kata timeline. TCP and process events for dd/nc / argus-gtc-network_burst-* on invisible-vm, plus sink-side receive on scenario-sink. DTS RX/TX sparklines may tick up. Demo label “Network Burst”. An excessive-data HIGH is documented by Argus, not guaranteed per click.
