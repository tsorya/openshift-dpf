    Explore scenarios

    Allowlisted actions

    These buttons select an action in the console above; use its separate Run button to execute it. The controller triggers only allowlisted actions in the management-cluster Kata VM. Argus observes from the HyperShift-hosted DPU cluster. The details below show the bounded commands and exact native evidence requirements.

    Discovery

    What it does. Runs bounded recon inside the Kata VM: uname -a, id, ps aux, then reads planted decoys at /decoys/credentials.txt and /decoys/runbook.txt. A single marked Python runner performs the checks without spawning temporary shell and sleep wrappers. No network, no privilege escalation.

    On the Kata timeline. Filter jumps to Discovery. Look for INFO · EVENT process activity from python3 /scripts/run-scenario.py, the recon commands, and file access on invisible-vm. Demo classification “Discovery (demo classification)” — not a native HIGH/ALERT.

    Executable Memory

    What it does. A Python process in invisible-vm writes inert bytes into an anonymous executable memory mapping and holds it for 45 seconds so Argus can sample it. It does not execute those bytes.

    Native evidence. Look for New Executable Anonymous Memory Mapped with message_type=EVENT and severity=WARNING, attributed to this Kata workload and run marker. Because Argus reports can arrive after the action, the controller waits up to 45 seconds for a match. It never labels process activity as a native detection.

    Audit Evasion Attempt

    What it does. Starts bounded Bash (bash --noprofile --norc -i) on a real Kubernetes exec PTY in the Kata VM. It establishes a harmless history baseline, waits for an Argus scan, clears history while history is enabled, waits again, then disables history and remains alive for another scan. The unique disposable history file is removed when the session exits.

    Success requirement. After the bounded action completes, the server waits up to 45 seconds for raw Argus output containing message_type=ALERT, severity=HIGH, and exactly Shell History Disabled or Shell History Cleared. The full request can take about 83 seconds. If no match arrives, the result says “No native alert observed”; INFO/EVENT telemetry remains visible and is never promoted to an alert.

    Reverse Shell Simulation

    What it does. Opens interactive bash (bash -i) and redirects stdin/stdout over /dev/tcp to the in-namespace scenario-sink for about 20 seconds. NetworkPolicy keeps the traffic inside the demo namespace — no internet C2.

    On the Kata timeline. Filter includes both invisible-vm and scenario-sink. Look for process events (bash -i / argus-gtc-reverse_shell-*) and TCP connect events to the sink. The controller waits up to 45 seconds for Argus’s native detection. Demo labels and network activity are not native alerts; report “Reverse Shell Detected” only if Argus emits it with message_type=ALERT and severity=HIGH.
